# eDirStat: CPU/GPU и ускорение плотной карты

18 ноября 2026. Сборка Windows x64 для релиза v2.2.0-plus.3.

## Что выполняется где

| Операция | До изменения | В новой сборке и почему |
|---|---|---|
| Чтение MFT и файловой системы | Диск/ОС + CPU, фоновые потоки | Оставлено: доступ к файловой системе, переменные записи, проверки путей и ошибки требуют CPU. Передача на GPU не устраняет чтение диска. |
| Разбор MFT, связи родителей, размеры папок, создание снимка | CPU | Оставлено: много переходов по дереву и зависимостей; результат нужен логике приложения и интерфейсу на CPU. В существующем MFT-сканере уже ограничено число потоков до 8, чтобы не перегружать память. |
| Постоянный кэш, сериализация и Zstd | CPU + диск, фоновая работа | Оставлено: используемый формат и библиотека работают на CPU; ускорение требует отдельного замера загрузки и сохранения. |
| Поиск дубликатов, BLAKE3 | CPU, Rayon для параллельной работы | Оставлено: сначала надо прочитать файлы. GPU-хеширование может быть полезно для больших пакетов уже находящихся в видеопамяти данных; для текущего дискового потока выгода не доказана. |
| Раскладка прямоугольников, детализация, отсечение вне экрана, выбор мышью | CPU | Оставлено: CPU нужен результат для наведения и работы с деревом. Перенос раскладки на GPU потребовал бы синхронизации/чтения результата обратно или отдельной системы выбора. |
| Скорость камеры, прогресс раскрытия и анимаций | CPU | Оставлено: это небольшой объём управляющих вычислений. Удалены лишние расчёты перемещения геометрии там, где оно не используется. |
| Крупные плитки, заголовки, интерфейс | CPU готовит меши/текст, GPU рисует | Сохранено. Подготовка текста и мешей egui не становится GPU-работой только потому, что приложение использует WGPU. |
| Мелкие файлы площадью менее 36 квадратных пунктов | CPU создавал картинку размером с карту, проходил её пиксели, вычислял градиенты/обводки; GPU получал готовую текстуру | Перенесено на GPU: CPU передаёт компактные экземпляры прямоугольников, шейдер вычисляет градиент и границу каждого покрытого пикселя. |

## Реализовано

- Новый WGPU-путь для мелких файлов: по одному instanced draw call на слой карты, 32 байта на плитку, шесть вершин формируются шейдером без отдельного массива вершин и индексов.
- Больше не создаётся и не отправляется полная RGBA-картинка мелких плиток на каждом изменяющемся кадре WGPU.
- GPU-буферы переиспользуются и растут только при нехватке ёмкости. Пока плитки не изменились, список экземпляров повторно не отправляется.
- Слои родительской и открываемой папки имеют отдельные буферы; порядок рисования и отсечение сохранены.
- Сохранены цвета, стили, анимация цвета, обводки, расчёт формы папок и логика выбора. Граница вычисляется в физических пикселях.
- CPU-путь оставлен для контекстов без зарегистрированного WGPU-рендерера, в том числе существующих headless-проверок. Native-приложение регистрирует GPU-путь через eframe CreationContext.
- CPU больше не вычисляет расстояния перемещения для каждого мелкого файла, когда геометрическая анимация выключена. Для применяемой геометрической анимации сравниваются квадраты расстояний без извлечения квадратного корня.

## Измерения

Release-сборка Rust 1.100.0, Windows x64. Проверка шейдера на NVIDIA GeForce RTX 5060, Vulkan, драйвер 617.14. Синтетическая карта 2560×1440, одинаковые данные и стиль Cushion, прогресс анимации 0,6. Для каждого случая — медиана девяти итераций, старый и новый алгоритмы запускаются в одном процессе.

| Размер плитки | Число плиток | Старое окрашивание CPU | Подготовка экземпляров CPU | Ускорение этого этапа |
|---|---:|---:|---:|---:|
| 3×3 px | 409 440 | 38,296 мс | 8,766 мс | 4,37× |
| 5×5 px | 147 456 | 32,756 мс | 3,243 мс | 10,10× |

При этих же размерах передача меняется с 14 745 600 байт картинки на 13 102 080 и 4 718 592 байт экземпляров соответственно. Во время неподвижного кадра повторной передачи экземпляров нет. Если одновременно видны два слоя во время входа в папку, каждый слой обрабатывается отдельно, как и раньше.

Это измерение CPU-этапа подготовки мелких плиток, включая создание и освобождение результата. Оно не включает время раскладки, остальные меши, отправку команд, выполнение GPU и показ кадра. Поэтому цифры не означают ускорение всей программы или FPS в 4–10 раз. GPU теперь выполняет работу окрашивания, и его нагрузка может вырасти. Загрузка диска/MFT этим изменением не ускоряется.

## Проверка

Выполнена адресная offscreen-проверка на реальной видеокарте, без управления рабочим столом: 27 изображений (9 стилей × 3 DPI: 1, 1,25, 2). В каждом изображении есть дробные координаты, обрезанные плитки и четыре значения прогресса анимации. Результат GPU сравнивается с прежней CPU-картинкой; допустимое отклонение — один уровень из 255 на канал. Проверка прошла. Полный набор тестов не запускался.

На расстоянии ровно 1,0 физического пикселя старый CPU-путь может классифицировать границу иначе из-за деления на DPI и ошибок float. В сравнении использованы дробные координаты без этого неоднозначного случая. Новый шейдер привязывает вычисления к центрам физических пикселей; это устраняет ошибку интерполяции координат на границе.

Итоговый exe собран через cargo build --release. Исходники, накопленный патч, журнал сборки, журнал адресной проверки и SHA256 находятся в архиве. Предыдущие сборки сохранены.

## Что ещё может ограничивать скорость

На плотной карте остаются CPU-расчёт раскладки и детализации, таблица состояний анимации, создание мешей крупных плиток и подготовка подписей. Следующий обоснованный шаг — замер полных кадров на реальном снимке диска и разделение времени этих стадий; переносить их на GPU без замера рано. Для более быстрой проверки кэша диска перспективен журнал изменений NTFS USN: это сокращение повторной работы CPU/диска, а не задача для GPU. Текущая проверка кэша по-прежнему выполняет новое чтение MFT.

## Изменённые файлы этого ускорения

- `crates/edirstat-gui/src/stats/treemap.rs`: подготовка экземпляров, выбор GPU/CPU-пути, кэш списков плиток, сокращение вычислений анимации, адресная проверка и замер.
- `crates/edirstat-gui/src/stats/treemap_gpu.rs`: переиспользуемые GPU-ресурсы и callback WGPU.
- `crates/edirstat-gui/src/stats/treemap_gpu.wgsl`: градиенты, однопиксельная обводка и преобразование цвета для sRGB-цели.
- `crates/edirstat-gui/src/stats/mod.rs`, `crates/edirstat/src/app.rs`: подключение GPU-пути.
- `crates/edirstat-gui/Cargo.toml`, `Cargo.lock`: bytemuck для безопасной передачи структур; pollster только для offscreen-проверки.
